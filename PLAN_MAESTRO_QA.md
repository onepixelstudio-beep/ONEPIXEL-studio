# Plan Maestro de QA Manual: OnePixel Studio v1.0

Este documento es la **Guía Oficial de Pruebas Manuales** para **OnePixel Studio**. Su propósito es estructurar de forma exhaustiva, rigurosa y sistemática el proceso de aseguramiento de la calidad (Quality Assurance) en la experiencia real de uso de la aplicación.

Cada caso de prueba ha sido diseñado basándose en el comportamiento real del código, las interacciones cruzadas de subsistemas y las directrices arquitectónicas de la aplicación. El objetivo es intentar "romper" el editor en situaciones límite para asegurar la máxima estabilidad de la versión 1.0.

---

## 📊 Resumen Ejecutivo del Plan de QA

El plan se divide en **10 Bloques Lógicos** de control de calidad, ordenados internamente de mayor a menor criticidad. Cada caso de prueba sigue el formato estándar:

| Campo | Descripción |
| :--- | :--- |
| **ID** | Identificador único estructurado (ej. `QA-CAN-001`) |
| **Subsistema / Funcionalidad** | Módulo e interacciones implicadas |
| **Objetivo** | Qué se quiere validar con exactitud |
| **Pasos Detallados** | Acciones secuenciales que el tester manual debe ejecutar |
| **Resultado Esperado** | Comportamiento esperado según las especificaciones técnicas del editor |
| **Prioridad** | **Crítica** (bloquea flujos principales o corrompe datos), **Alta** (UX defectuosa o error de función principal), **Media** (error menor en flujos secundarios), **Baja** (estética o pulido visual) |
| **Estado** | `Pendiente` (por defecto) \| `Aprobado` \| `Falló` \| `No aplica` |
| **Observaciones** | Registro de fallos, logs de consola o capturas de comportamiento |

---

## 🛠️ Instrucciones de Uso para el QA Tester

1. **Entorno de Pruebas**: Se recomienda abrir la aplicación en el navegador bajo condiciones normales de desarrollo o preview y tener abierta la consola del navegador (`F12`) para detectar cualquier advertencia o excepción de React/TypeScript no controlada.
2. **Uso del Historial**: Para pruebas relacionadas con el historial de deshacer/rehacer (`Undo/Redo`), recuerde usar los atajos rápidos (`Ctrl+Z` / `Ctrl+Y`) o los botones de interfaz correspondientes para comprobar que el estado se recupera con total fidelidad.
3. **Registro de Fallos**: En caso de fallo (`Falló`), por favor documente en la columna de *Observaciones*:
   - El paso exacto en que falló.
   - Si se generó una excepción de JavaScript (vía Consola).
   - El ID de la incidencia para su posterior corrección individual.
